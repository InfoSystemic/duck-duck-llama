# DeepSeek-V4.1-Flash upstream engineering assessment

Observed 2026-09-12. This is an evaluation of current source and published artifacts, not a claim that a replacement runtime has passed on this host. No model weights were downloaded. Exact Hugging Face file sizes, LFS SHA-256 values and revisions are recorded in `deepseek-v41-hf-files-20260912.json`.

## Recommended implementation route

Use an isolated checkout of `JigSawPT/llama.cpp`, branch `dsv41-porte`, pinned to **3b6fcfe4f7e2c282076f0c159278d3acfa3ad4e5** (2026-09-11 17:32:16 UTC). It is the most complete inspected V4.1 graph: shared compressed caches, hierarchical candidate selection, raw FP8 Engram, delayed hyper-connections and DSpark semantics. Build CPU-only, leave expert streaming disabled, then bring over the host's proven NUMA kernels after establishing correctness. An isolated port avoids entangling the working GLM/Qwen engines with changes across the model loader, cache and graph. This is a reasoned choice from source coverage; neither x86 speed nor full long-context fidelity is proven. [Pinned implementation](https://github.com/JigSawPT/llama.cpp/tree/3b6fcfe4f7e2c282076f0c159278d3acfa3ad4e5), [branch engineering notes](https://github.com/JigSawPT/llama.cpp/blob/3b6fcfe4f7e2c282076f0c159278d3acfa3ad4e5/README-dsv41.md).

Do not replace the native runtime with a lower-bit quant merely because a file fits. The published JigSaw GGUF preserves released MXFP4 expert blocks and raw FP8 Engram, but does **not** preserve native FP8 linear or activation/cache arithmetic. It is a candidate for comparison, not an exact native-precision substitute.

## Source-level correctness assessment

The local official config specifies 40 backbone layers, KV sources `[2,8,14,20]`, index sources `[2,8,14,20,24,28,32,36]`, ratios 2 through layer 19 and 1 from layer 20, candidate source 20, 2,048 candidate blocks of eight positions, and Engram layers 1 and 14. Thus checking only 256 or 1,401 tokens cannot exercise the candidate pruning required above 16,384 positions at the decoder's ratio 1.

JigSaw's loader reads the explicit KV/index source lists and maps each layer to its latest KV source. Its graph resolves source cache rows instead of recompressing at every consumer. The compressor disables V4's overlapping groups for V4.1. Its candidate path pools score maxima by block, pins the newest block, selects blocks and applies the mask after the candidate source. Its V4.1 query path skips V4's incorrect per-head q RMS normalization. Those features exist in source, but boundary behavior and numerical equivalence still need execution against the pinned official model. [Graph, especially lines 127–168, 849–899, 1002–1009, 1286–1291](https://github.com/JigSawPT/llama.cpp/blob/3b6fcfe4f7e2c282076f0c159278d3acfa3ad4e5/src/models/deepseek4.cpp), [cache ownership and non-overlap](https://github.com/JigSawPT/llama.cpp/blob/3b6fcfe4f7e2c282076f0c159278d3acfa3ad4e5/src/llama-kv-cache-dsv4.cpp).

JigSaw stores Engram weight bytes plus one E8M0 scale per 32 columns and deterministic hash tensors. `--engram` is essential: without it the converter intentionally omits conditional memory. The V4.1 converter checks the compressed vocabulary equals 99,092 and prime totals match the actual table sizes; the two tables have different row counts. The vcruz files instead use GGUF-quantized Engram and metadata hash arrays, so the two formats are not interchangeable. [JigSaw converter](https://github.com/JigSawPT/llama.cpp/blob/3b6fcfe4f7e2c282076f0c159278d3acfa3ad4e5/conversion/deepseek_v41.py), [row decoder/hash](https://github.com/JigSawPT/llama.cpp/blob/3b6fcfe4f7e2c282076f0c159278d3acfa3ad4e5/src/llama-engram.cpp).

The inherited JigSaw conversion path reads FP8 block size from configuration, avoiding V4's incorrect fixed-128 assumption for V4.1's 32×32 blocks. However, `tensor_force_quant()` lines 897–909 **forces every dequantized FP8 matrix to Q8_0 even when `--outtype bf16` was requested**. Therefore a native-fidelity conversion needs an explicit override or raw-FP8 storage path. Dequantization to BF16 must itself be verified tensor-by-tensor; activation FP8/FP4 and cache rounding still require native operators even if weight values are preserved. [Conversion source](https://github.com/JigSawPT/llama.cpp/blob/3b6fcfe4f7e2c282076f0c159278d3acfa3ad4e5/conversion/deepseek.py).

Before concurrent serving, audit Engram state isolation: `set_input()` records only `seq_id[i][0]`, not every sequence sharing a token; its timing counters are mutable function statics, and `e4m3_table()` uses an unsynchronized mutable static `built` flag. These are concrete source-level risks for shared-prefix batches or concurrent contexts; no failing multi-context execution was claimed or attempted. Initial graph tests should use one sequence. [Engram input state](https://github.com/JigSawPT/llama.cpp/blob/3b6fcfe4f7e2c282076f0c159278d3acfa3ad4e5/src/llama-graph.cpp).

vcruz's conversion PR is open/draft, not merged. Its author repaired missing Engram keys and the wrong `deepseek4.engram.*` prefix on September 11. Old copies must not be reused based only on filename. Q1_0 repeatedly emitting one token is a known unusable rung. [Conversion PR and dated author reports](https://github.com/ggml-org/llama.cpp/pull/28696).

## Confirmed Linux performance defect

`llama_prefetch_ranges()` at JigSaw `src/llama-mmap.cpp:1241` passes unaligned pointers directly to `posix_madvise(..., POSIX_MADV_WILLNEED)` and ignores the return value. Engram callers pass arbitrary 256-byte rows and eight-byte scale rows. Linux requires the start address to be page-aligned. A local two-page anonymous-mapping probe returned **0 for an aligned pointer, EINVAL (22) for +256 and +8 offsets**, on 4,096-byte pages. Most prefetch requests therefore silently do nothing on this host. [Caller](https://github.com/JigSawPT/llama.cpp/blob/3b6fcfe4f7e2c282076f0c159278d3acfa3ad4e5/src/llama-graph.cpp), [prefetch implementation](https://github.com/JigSawPT/llama.cpp/blob/3b6fcfe4f7e2c282076f0c159278d3acfa3ad4e5/src/llama-mmap.cpp), [Linux system-call contract](https://man7.org/linux/man-pages/man3/posix_madvise.3.html).

Required fix: align each range's start downward and cover its original endpoint, safely handle empty/overflow ranges, and preferably coalesce overlapping pages. This changes read-ahead hints only. Test calls captured from the actual implementation and successful real system calls, including crossing a page boundary. It does not justify any claimed end-to-end speedup until a model workload is measured.

## Host fit and next engineering gates

At inspection: 755 GiB physical RAM, 241 GiB available, all 8 GiB swap occupied; root filesystem only about 3.2 GiB free. A 467.347-GiB JigSaw image can fit in total physical memory in isolation, but cannot be downloaded to current free disk or loaded alongside current allocations without planning. vcruz Q8_0 is 473.069 GiB; Q4_K_M 414.194 GiB; Q3_K_M 323.422 GiB; Q2_K 246.349 GiB. Lower-bit files are not the proposed native-fidelity solution. Scratch conversion would require much more storage than the final file. Reuse existing native checkpoint storage or provision space before any full weight operation.

1. Isolate and build the pinned JigSaw source CPU-only with native x86 instructions; disable CUDA/Metal and expert streaming. Use spare cores and bounded build concurrency during other benchmarks.
2. Run real graph fixtures for Engram hashing, HC lag, ratio-1/ratio-2 compressor tails, shared KV/index ownership, prefill split at odd positions and chunk-size invariance. Compare against the existing CPU-patched official reference, which is a usable oracle.
3. Exercise candidate selection around 16,383/16,384/16,385 and partial eight-position blocks. Test newest-block pinning, all-minus-infinity unreachable blocks, candidate source/consumer causality and sequential versus chunked input. Presence of source code does not prove this gate.
4. Preserve released MXFP4/raw-FP8 storage and native activation/cache rounding. Keep the existing native engine as the numerical baseline; compare layer tensors, routes, logits and held-out corpus likelihood before promotion. A same-argmax smoke test is insufficient.
5. Add four-node placement only after correctness: first compare one socket versus four with interleaved memory, then distribute packed expert rows across sockets and bind workers to local rows. Reuse proven local native kernels where their exact arithmetic matches; avoid replicating the entire 467-GiB model per socket. Tune prefill and decode separately and measure cross-node traffic/latency.
6. Validate realistic fresh conversations, repeated-prefix sessions, rollback/state save/load, and long-context recall before publishing a 16K+ endpoint. Vision remains an explicit unverified capability. Do not derive encoder-only prompt skipping from CED branding: the complete reference executes decoder layers during ordinary prefill, and exact skipping needs its own receptive-field proof.

This assessment changes the next action from extending an incomplete V4 graph by guesswork to testing a nearly complete independent V4.1 graph with an available CPU oracle. It leaves native precision, long-context correctness and host throughput as explicit unfinished requirements.

## Local work completed after assessment

The POSIX prefetch range fix is implemented there and exported as `jigsaw-posix-prefetch.patch`. `test_prefetch_ranges.cpp` compiles the actual `llama-mmap.cpp` and wraps `posix_madvise` only to record arguments and call the real libc function.

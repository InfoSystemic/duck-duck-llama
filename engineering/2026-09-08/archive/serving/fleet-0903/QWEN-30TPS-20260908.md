## Lossless Q6 byte-layout prototype

The selected Q6 x16 kernel repeatedly extracts six-bit codes from packed
weights. qwen-q6-lossless-bytes-0908.h prototypes a byte layout containing the
same codes, signed scales, and fp16 factors, with no re-quantization. A block
grows from 3360 to 4384 bytes, about 30.5% more storage for the affected Q6
tensors. Other tensor types are not changed by this prototype.

The standalone primitive passed 432 cases: 29,376 outputs match the selected
native kernel and an independent scalar reference bit for bit, with zero
reference error. All 20,193,280 checked codes and copied scale/factor bits were
preserved. Widths include 2560 and other tested multiples of 256; row counts
include the model's 32/64-row tiles and 160-row socket geometry. The proof and
exact compile command are in
results/qwen-q6-lossless-bytes-prototype-0908/result.json. No model library,
weight file, or service was changed by this standalone test.

The first component timing run compiled successfully and checked output
equality across its matrices. It used CPU 127 after initializing with all 128
CPUs available, and native/expanded/expanded/native timing order. Two warm
32/64-row cases stayed within the background CPU gate and improved by about
22%/33%. All streaming cases and the 160-row warm case crossed that gate; the
overall timing result is failed and cannot establish a cold-weight benefit.
Evidence is in results/qwen-q6-lossless-bytes-component-0908/result.json.

The next useful qualification is uncontended timing with multiple distinct
activation rows per expert, matching the MTP reuse pattern, as well as the
single-activation cold case. The expanded layout must improve useful kernel
throughput before model integration; extra traffic alone is not a speed gain.
No full-model improvement is claimed for this prototype.

A read-only host audit found automatic NUMA balancing disabled and transparent
huge pages in madvise mode. The queried cpufreq/intel_pstate policy files were
absent, so no CPU frequency-policy conclusion is drawn and no settings changed.

## HC multiplication and stream mean: exact graph proof

qwen-hc-mix-0908.h fuses the product of normalized stream values and sigmoid
gates, the left-to-right stream sum, and its final mean. It uses the existing
custom graph API and 256-element work tiles. Normalization, gate projections,
sigmoid, injection projection, and model weights are unchanged. Each product
rounds before addition, the original addition order is preserved, and FP32
contraction is disabled. The first product initializes the sum directly so

## Flattened HC normalization: exact proof and private runtime

Source review found that native RMS normalization distributes ne[1] rows over
workers but loops serially over ne[2]. The original HC tensor has shape
[width, streams, tokens], exposing only four stream rows even during multi-token
verification. Its reshape also separates RMS_NORM from MUL in the graph,
preventing the existing adjacent-node fusion.

qwen-hc-norm-flat-0908.h reshapes contiguous input to
[width, streams*tokens], preserving the order and arithmetic of each row's
mean and normalization. It reshapes the gamma weights to [width, streams],
places that weight view before the normalization nodes, then performs the
existing RMS_NORM/MUL sequence and reshapes the result back. Padded input uses
the original graph. No quantized weights or CPU arithmetic kernel changes.

The proof passed 576 CPU cases at 1/4/15 workers and 192 four-NUMA cases at
15 workers/socket. All 35,892,640 outputs match the original graph and an
independent scalar calculation bit for bit. It covers widths 256/257/2560,
one/four streams, 1/3/5/64 tokens, normal/padded input, signed gamma values,
zero/one gamma values, large finite inputs, and negative zero. Inputs and
padding remain unchanged. Half the cases check the padded fallback; half
verify that contiguous rows expose RMS_NORM/MUL adjacency accepted by the
existing fusion predicate. This eligibility count is not an execution counter:
single-thread and small-tensor scheduling can bypass fusion. Evidence:
results/qwen-hc-norm-flat-proof-0908/result.json.

The private builder reproduces the HC stream-mean parent object and library
byte for byte, then changes only qwen4exp.cpp.o behind
GGML_QWEN_HC_NORM_FLAT. Its llama SHA-256 is
d0b2321eae443255dd84a5ad98cda8d3d9bf5540a31891bdc5c03be91061d647.
The loader passes with unchanged C79 CPU/server bytes and all four NUMA
devices. Both off/on model plans fix HC-combine and stream-mean fusion enabled.

results/qwen-hc-norm-flat-build-0908/result.json and

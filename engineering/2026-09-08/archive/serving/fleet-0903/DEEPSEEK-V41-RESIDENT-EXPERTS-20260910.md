# DeepSeek V4.1 native CPU: retain cached expert mappings

DeepSeek-V4.1-Flash remains available at `http://127.0.0.1:18170/v1`, using the released FP8/FP4 text checkpoint. Keeping cached experts mapped raises matched warm decode from **0.659 to 1.094 tok/s**, a **1.660×** improvement. The selected HTTP endpoint independently measures **1.096 tok/s** on the same cached greeting. These are short, single-request measurements on 16 physical cores of one socket.

| Matched path | First warm decode | Second warm decode | Combined decode |
| --- | ---: | ---: | ---: |
| Original demand mappings | 0.664 tok/s | 0.653 tok/s | 0.659 tok/s |
| Retained native mappings | 1.087 tok/s | 1.100 tok/s | 1.094 tok/s |

The prompt is `Hi.` (six tokens). Every response is `Hello! How can I help you today?`, with ten generated tokens including EOS. Decode rates count the nine forward passes after prefill. Two timed controls bracket two timed candidate requests; each path has a separate warmup. All six requests run in fresh threads matching the HTTP server, with 16 workers and affinity 48–63. Every request downloads zero bytes. All 60 per-step logit hashes match the original real-model run exactly. This establishes repeatability against the existing CPU implementation; broad quality and GPU-reference parity are still unmeasured.

The old path mapped and rebound six parameters for every selected expert, then immediately returned the module to meta tensors. It performed 18,432 tensor loads per complete greeting. The new path retains 1,559 touched experts in the existing cache and performs **zero tensor reloads** on the two measured candidate greetings. It also avoids repeated file checks for already verified resident parameters. The published checkpoint bytes and arithmetic remain unchanged. Retaining mappings creates no second weight copy.

The 90 GiB cache cap and expert-group LRU policy remain in force. Eviction releases mapped parameters even if the following download fails, and requested experts remain protected. Six small native-format fixtures exercise reuse, eviction with a failed download, protected experts, exact FP4/scale reload, scale aliases, and complete unmapping. The real trial then validates the full text graph and request reset. The controller targets the old server through a pidfd, hands off its lifecycle lock, validates the promoted endpoint, and can restore the previous implementation if promotion startup fails. The selected GLM Flash process is preserved.

The initial HTTP cycle profile contains 4,274 samples wholly inside cached decode. Native FP4 and FP8 kernels account for 31.68% and 27.72% of sampled user cycles. Those shares are not wall-time fractions. A separate main-thread CLI profile includes PyTorch DeviceContext dispatch overhead that the HTTP request threads do not inherit; its inclusive timers overlap. It is retained as diagnostic evidence, and the speed comparison above uses HTTP-style threads instead.

The cache contains 38,841,841,088 native tensor bytes, plus persisted Engram rows. It is temporary across reboot. Context remains 256 combined tokens, output at most 128 tokens, text only and greedy. Cold prompts can fetch missing experts and Engram rows. The entire 510 GB checkpoint is not resident. Vision, DSpark, longer contexts, four-socket execution, broad quality evaluation, and IMC bandwidth measurement remain open. No 250 GB/s, 85%, or 93% bandwidth claim is established.

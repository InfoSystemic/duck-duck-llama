flash-rms-guarded-0908.h vectorizes the double-precision accumulation of
float32-rounded squares, then bounds its difference from the original
serial sum. It accepts a mean only when both outward interval endpoints
round to the same float32 bits. Otherwise the original serial calculation
runs. Scale calculation, epsilon, subsequent multiplication, weights, and
row scheduling are unchanged. Reference mode always retains the original.

The error argument uses the summation-tree bound from Nicholas J. Higham,
[The Accuracy of Floating Point Summation, section 2](https://nhigham.com/wp-content/uploads/2023/10/high93s.pdf).
For finite nonnegative float32 squares converted exactly to double, each
sum has relative error bounded by gamma_n = n*u/(1-n*u), with u=2^-53.
The difference between serial and vector sums is at most
2*gamma_n/(1-gamma_n) times the computed vector sum. At n <= 2^24,
4*n*DBL_EPSILON provides a conservative wider bound, including its own
rounding. nextafter expands the interval outward at subtraction, addition,
and division. Float32 conversion is monotone; matching endpoint bits enclose
the original mean. This interval construction is our application of the
paper's bound. Inputs shorter than 1,024 or longer than 2^24, nonfinite
squares, unsupported instructions, unsuitable rounding/exception modes,
and rounding-boundary ambiguity take the original path. These finite
double sums and divisions do not underflow or overflow in the allowed
range. The direct probe covers all four FTZ/DAZ settings.

## September 8 synchronization candidate and external launch collision

The latest raw profile was also grouped by lead versus other NUMA workers in
results/glm-flash-q8-r8-ordered-k-profile-0908/analysis/thread-summary.json.
The four lead workers have 9.73% of sampled periods in verified OpenMP waits;
the remaining 56 have 29.46%. Source inspection shows the fused NUMA graph
already avoids most per-layer OpenMP region launches. The remaining graph
barriers motivate a private load/store dissemination barrier. Sampled CPU
cycle fractions do not establish removable elapsed time.

The algorithm follows the [Rochester synchronization pseudocode](https://www.cs.rochester.edu/research/synchronization/pseudocode/ss.html):
workers exchange cache-line-separated flags over logarithmic rounds, with
release/acquire publication, alternating parity and sense. The CPU engine
selects it only with GGML_CPU_DISSEMINATION_BARRIER=1 and 2-64 actual workers.
Single-worker and larger teams retain the existing path. Flags are initialized
before graph work and cursors reset per graph. No OpenMP tasks were found in
the affected CPU/meta graph sources; this candidate does not implement OpenMP
task scheduling semantics.

The first standalone probe passed correctness but its timings are excluded:
the executable inherited the controller's one-CPU startup affinity, causing
libgomp to see one available processor. The [GCC 13 Linux wait implementation](https://raw.githubusercontent.com/gcc-mirror/gcc/releases/gcc-13/libgomp/config/linux/wait.h)
uses a throttled spin count when managed threads exceed available processors.
The corrected probe starts with all 128 logical CPUs visible, then pins workers
internally. It verifies the same libgomp file and SHA as the model. The corrected
probe finished before the external Qwen launch, so that launch did not
contaminate these component measurements.

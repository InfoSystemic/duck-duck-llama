libggml-base, Meta (tensor-parallel) backend on CPU-NUMA devices: small uploads without threads, dispatch waits that block.
DEPLOYED 2026-09-20 (revision e). No numerical effect: text hash, accepted drafts and log-probabilities identical.
GGML_META_F18=<mask> (default 0): bit 1 = uploads below GGML_META_F18_SET_TENSOR_PAR_MIN bytes (default 1 MiB) run in the calling
thread; bit 0 = the main thread and the per-device dispatch threads block at once. GGML_META_F18_CONTROL_FILE maps a 4-byte word
for in-process A/B. Two diffs below: [1] the parent of this patch against the published engine source (the non-temporal-store
all-reduce already in production since 09-14, the GLM-line twin of numa-reduce-nontemporal-stores.patch), [2] this patch.

How it was found. perf is not available on this host (perf_event_paranoid=4, no root), so the host side was measured with what an
unprivileged user has: per-thread /proc/PID/task/*/stat deltas over one decode (faults, user/system time, context switches, CPU
placement, run state and wait channel), the cgroup's memory.stat, /proc/interrupts, and strace -f --seccomp-bpf on an 8-layer
proxy started as strace's own child. strace showed 5,322 madvise(8 MB, MADV_DONTNEED) calls in a 57-cycle decode: thread stacks
being recycled, ~93 thread creations per decode cycle.

[bit 1] ggml_backend_meta_buffer_set_tensor starts one std::thread per NUMA device for EVERY call on a CPU-NUMA buffer group. That
is right for weights at load time. It is also the path of every graph input (tokens, positions, masks, KV and pool indices, MTP
hidden rows) and of uploads that happen inside graph compute: clone, 8 MB stack, arena mmap, TLB shootdowns into the 60 cores that
are computing, and the transient threads land on worker CPUs (worker preemptions 32 -> 6 per cycle once they are gone).
[bit 0] Between graphs the main thread and the eight dispatch threads (four per context) wait with 300 us of pause and then
sched_yield() for up to 20 ms before blocking. They are unpinned and sit on the hyperthread siblings of worker cores, where a
syscall-spinning sibling slows the one worker every barrier then waits for. Pinning them to the spare cores instead was -9% on
09-19 (background jobs live there). The load-time knobs GGML_CPU_NUMA_DISPATCH_SPIN_US=0 / _HARD_SPIN_US=0 do the same as bit 0.

# GLM exact-input pooled-result cache

Private CPU-only candidate, disabled by default, not deployed. The previous Q8 candidate is not included. The parent is the current deployed wider-pool CPU library, SHA256 3f957a341321b940d93be53c250cdd068825093faa2d9efda142ebe56427b1b3.

Reuse the fused pooling output only after byte comparison of every input that determines it: all four F16 key/gate rows (256 half values per member), all four F32 position-weight rows, the multiply operand order, and floating-point control state. Cache identity uses source data addresses only as lookup hints; actual input equality authorizes reuse. Slot mapping is always resolved and range checked before any hit. Pool visibility and scoring remain outside this cache and run normally.

The existing wider kernel arithmetic and its 8-channel partition remain unchanged. Cache only full 128-channel pools wholly assigned to one worker; boundary fragments and other dimensions execute the existing path. Cache misses save inputs, run the existing arithmetic, then save the 128 output floats. Each worker owns its records in thread-local storage. No graph tensor, model memory, scheduler or cache format changes.

Each source entry has up to 2,048 pool records, and each worker retains up to 16 entries under a 64 MiB data limit. A process-wide 4 GiB reservation limit bounds all records, including growth allocations. Allocation failure falls back to computation. Large contexts cache a bounded segment of each worker's assigned pools; remaining pools compute normally. Cache input comparisons avoid hash-collision correctness assumptions and detect append, rollback/overwrite, cell reuse, restore, stream changes, pointer reuse and position-weight changes. Cache storage survives off/on toggles, but no old entry can hit without checking current bytes.

Gates before any service use: rebuild the exact parent; run existing fused/unfused graph parity; stress repeated hits, one-byte changes in every input class, append/rollback-style edits, map rebasing, full restore, multiple sources/streams, stride changes, partial worker partitions, thread-count changes, arena/address reuse, dynamic mode toggles, floating-point-control changes, bounded allocation/eviction, and candidate off/on parity. Compare complete output bytes with the deployed library. Measure cold and repeated workloads separately at short, 32K and 100K pool shapes. Then use the four-NUMA graph and a private model A/B only if the gain remains material. Synthetic throughput is not model tok/s.
